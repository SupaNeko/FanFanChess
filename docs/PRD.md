# 翻翻棋网页对战游戏 - 产品需求文档 (PRD)

## 1. 产品概述

### 1.1 产品名称
翻翻棋在线对战平台

### 1.2 产品定位
轻量级网页端双人策略棋类游戏，支持本地对战和在线联机对战。

### 1.3 目标用户
- 喜欢中国传统棋类游戏的休闲玩家
- 需要短时对战的网页游戏用户
- 想和朋友在线对战的社交玩家

## 2. 核心业务流程

### 2.1 用户访问流程
1. 用户访问网站首页
2. 输入用户名（唯一标识，不可重复）
3. 选择对战模式（本地模式 / 联机模式）
4. 进入对应游戏流程

### 2.2 本地模式流程
1. 用户选择本地模式
2. 后端随机打乱棋盘
3. 显示抛硬币动画决定先手
4. 先手翻棋确定颜色绑定
5. 双方交替操作直至游戏结束

### 2.3 联机模式流程
1. 用户选择联机模式
2. 选择创建房间或加入房间
3. 创建房间生成6位邀请码
4. 其他用户通过邀请码加入
5. 前两位进入者为玩家，后续为观战
6. 玩家点击"准备"
7. 双方都准备后，抛硬币决定先后手
8. 先手翻棋确定颜色绑定
9. 开始对局

## 3. 功能需求

### 3.1 用户系统 (P0)
- 用户名注册/登录（无密码，仅用户名唯一绑定）
- 用户名唯一性校验
- 用户状态管理（在线、游戏中、观战）

### 3.2 本地模式 (P0)
- 单人双角色操作
- 棋盘随机打乱
- 先后手判定
- 颜色绑定机制
- 完整的游戏逻辑

### 3.3 联机模式 (P0)
- 房间创建（6位随机邀请码）
- 房间加入（输入邀请码）
- 玩家与观战者区分
- 准备阶段机制
- 实时对战通信
- 断线重连（基础版本）

### 3.4 游戏核心逻辑 (P0)
- 棋盘状态管理（4x8）
- 棋子移动验证
- 吃子规则验证
- 翻棋机制
- 胜负判定
- 和局判定
- 投降功能

### 3.5 悔棋功能 (P1)
- 发起悔棋请求
- 对方同意/拒绝机制
- 回退到上一步状态

### 3.6 历史记录 (P1)
- 每步操作记录
- 对局完整历史存储
- 基础复盘功能

### 3.7 UI表现 (P0)
- 横置棋盘（4行8列）
- 左右两侧棋子统计
- 回合提示
- 上一步操作高亮
- 规则浮窗
- 抛硬币动画

## 4. 非功能需求

### 4.1 技术栈
- 前端：原生 HTML5 + CSS3 + JavaScript（零框架依赖）
- 后端：Node.js + Express + ws + sqlite3
- 数据库：SQLite（轻量化，零配置）

### 4.2 性能要求
- 首屏加载 < 2s
- 操作响应 < 100ms
- 支持同时在线 50+ 房间

### 4.3 部署要求
- 单命令启动
- 跨平台（Linux/Windows）
- 单端口服务（HTTP + WebSocket）

## 5. 游戏规则详情

### 5.1 棋子设置
- 帅/将 ×1
- 仕/士 ×2
- 相/象 ×2
- 車 ×2
- 馬 ×2
- 炮/砲 ×2
- 兵/卒 ×5
- 总计32枚棋子

### 5.2 棋子大小
帅 > 仕 > 相 > 馬 > 車 > 炮 > 兵
特殊：帅不能吃兵，反而被兵吃

### 5.3 走法规则
- 炮：不吃子时横竖走一格；吃子时必须隔恰好一个棋子，可吃任何已翻开棋子
- 其他棋子：横竖向移动一格
- 相同棋子互吃：双方同时消失
- 未翻开棋子不能被吃

### 5.4 翻棋规则
- 先手随机决定
- 第一个翻开的棋子颜色决定玩家阵营
- 可翻任意未翻开棋子

### 5.5 胜负条件
- 吃光对方所有棋子 → 胜利
- 双方同时无棋子 → 和局
- 一方投降 → 对方胜利

## 6. 数据模型

### 6.1 用户表 (users)
- id: INTEGER PRIMARY KEY
- username: TEXT UNIQUE NOT NULL
- created_at: TIMESTAMP

### 6.2 房间表 (rooms)
- id: INTEGER PRIMARY KEY
- code: TEXT UNIQUE NOT NULL
- creator_id: INTEGER
- status: TEXT (waiting/playing/finished)
- created_at: TIMESTAMP

### 6.3 对局记录表 (games)
- id: INTEGER PRIMARY KEY
- room_id: INTEGER
- red_player: TEXT
- black_player: TEXT
- winner: TEXT
- moves: TEXT (JSON)
- created_at: TIMESTAMP

## 7. API / 消息协议

### 7.1 WebSocket 消息类型
- `login`: 用户登录
- `create_room`: 创建房间
- `join_room`: 加入房间
- `ready`: 玩家准备
- `start_game`: 开始游戏
- `flip`: 翻棋
- `move`: 移动棋子
- `eat`: 吃子
- `surrender`: 投降
- `request_undo`: 请求悔棋
- `response_undo`: 响应悔棋
- `game_over`: 游戏结束
- `disconnect`: 断开连接

### 8.2 模式选择

### 8.4 房间页

- 玩家列表及状态
- 准备按钮

### 8.5 游戏页
- 横置4x8棋盘
- 左右棋子统计（棋子图标 × 数量）
- 顶部玩家信息 + 回合提示
- 右上角规则按钮（hover浮窗）
- 底部操作按钮（悔棋、投降）
